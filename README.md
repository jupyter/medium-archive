# Archive of the Jupyter Blog: blog.jupyter.org on Medium

**Disclaimer: The code and documentation in this repo is almost entirely generated from guided Claude sessions. The main value of this repo is the archive of the https://blog.jupyter.org Medium blog in the `archive/` directory**

The code in this repo does several things:

1. Maintain an archive of the https://blog.jupyter.org Medium blog in the `archive/` directory
   1. Check urls and content against archive.org
   2. Ingest Medium exports from article authors
2. Generate Hugo, Pelican, and Myst static sites containing the archive content

If we were to migrate to a static site, we could

1. Generate a static site using this repo.
2. Create a new repo for this static site, which would be the source of truth for the blog going forward.
3. Archive this repo as a snapshot of our blog at this point in time.

The information in the rest of this document is generated by Claude.

## Repository layout

```
src/medium_archive/   the tool (`medium-archive` command)
tests/                offline test suite: `pixi run test`
archive/              the Jupyter blog archive (340 posts); see archive/README.md
site/                 site.toml and the images it names, read by the site exporters
docs/                 analyses behind the generator and renderer choices

```

Generated and git-ignored: `archive/posts/`, `site-hugo/`,
`site-pelican/`, `site-myst/`, `.image-cache/`.

CI: `Tests` runs the suite in the pixi environment; `Lint embeds`
reconverts the archive and runs `lint --embeds`; `Preview sites` builds
all three sites to GitHub Pages on pushes to `main`.

`archive/raw/` is about 835 MB. To work on the tool only:

```sh
git clone --filter=blob:none https://github.com/jasongrout/medium-archive
cd medium-archive
git sparse-checkout set src tests docs
```

The archive was developed in
[jasongrout/blog_export](https://github.com/jasongrout/blog_export)
until 2026-09; `docs/blog_export-commit-map.txt` maps its commits to
this repository's.

## Installation

`pixi.toml` describes one environment with everything: Python 3.11+,
the tool (installed editable from the checkout), ffmpeg, gifsicle,
Hugo, Pelican, MyST, Pagefind and the test dependencies, all from
conda-forge except Pagefind (PyPI). With [pixi](https://pixi.sh):

```sh
pixi install                      # create .pixi/envs/default from pixi.lock
pixi run medium-archive --help    # run any command in it
pixi run test                     # the test suite
```

Every command in this README runs through `pixi run`, as CI does. The
tool's commands are `pixi run medium-archive <command>`. The pixi
tasks cover only what takes more than one command:

| task | runs |
|---|---|
| `test` | `pytest -q` |
| `build-hugo` | `medium-archive hugo`, then `hugo` and Pagefind in `site-hugo/` |
| `build-pelican` | `medium-archive pelican`, then `pelican` and Pagefind in `site-pelican/` |
| `build-myst` | `medium-archive myst`, then `myst build --html` in `site-myst/` |
| `pagefind` | `python -m pagefind` (its PyPI package installs no `pagefind` executable) |

`medium-archive hugo|pelican|myst` only writes a site's sources; the
`build-*` task is what produces the built site.

`fetch --solve-walls` needs Playwright and a browser, in a separate
environment:

```sh
pixi run -e solve-walls playwright install chromium
pixi run -e solve-walls medium-archive fetch URL --solve-walls
```

### External tools

The site exporters place every animated gif as an H.264 clip with a
webp poster, and stop with an error when they cannot (see
[Images](#images)). Building a site from an archive with animated gifs
therefore requires Pillow and an `ffmpeg` built with libx264, libaom
(the Pelican site's AV1 masters) and libwebp, unless `site.toml` sets
`[images] animated_format = "gif"`.
The other tools are needed only for the step that uses them. The pixi
environment has all of them, at the versions `pixi.toml` pins.

| tool | needed for |
|---|---|
| `ffmpeg` with libx264 and libwebp | `hugo`, `pelican`, `myst` exporters, when the archive has animated gifs |
| `gifsicle` | resizing gifs kept as gifs (`animated_format = "gif"` with `animated_max_edge` set) |
| `hugo`, extended, 0.156+ | building the Hugo site |
| `pelican` with markdown-it-py, mdit-py-plugins, pyyaml, pillow | building the Pelican site |
| `myst` (mystmd) | building the MyST site |
| `pagefind` | search on the Hugo and Pelican sites |

`pixi.toml` asks for conda-forge's `gpl` ffmpeg build, because its
`lgpl` builds omit libx264. To check an ffmpeg: `ffmpeg -hide_banner
-encoders | grep -E 'libx264|libwebp'`, or `pixi run ffmpeg ...` for
the environment's. CI builds the preview sites with the same
environment and the same `build-*` tasks.

## Commands

Only `fetch`, `all` and `import-ghost` use the network. Every command
takes `--archive DIR` (default `archive/`). Run `pixi run
medium-archive <command> --help` for all options.

| command | does |
|---|---|
| `fetch URL` | Download each post's page HTML, RSS item, full-size images and embed content (gist files, tweets, Carbon code, Giphy media) into `archive/raw/`. Incremental and resumable. |
| `import-export ZIP` | Merge a Medium account export (Settings → Download your information) into `raw/`. Only posts already archived, unless `--all`; `--drafts` includes drafts. |
| `import-ghost URL` | Recover posts from a Ghost-era blog via Wayback Machine captures. |
| `compare` | Convert posts that have both a page and an export from each source and diff the results. Exits non-zero on differences. `--state` checks the editor-state conversion; `--ghost` diffs Ghost captures against the Medium conversion. |
| `convert` | Convert `raw/` to Markdown in `archive/posts/`, plus `posts.json` and `redirects.csv`. Offline. |
| `hugo`, `pelican`, `myst` | Build a site from the converted posts into `site-<generator>/`. |
| `lint` | Report conversion defects: leftover Medium chrome, unclosed fences, missing or remote images, emphasis CommonMark will not parse, embeds whose media was never archived. Exits non-zero on a defect. `--embeds` also fails on embeds without archived content; `--seo` warns on missing/long descriptions, long titles, missing alt text, missing covers, duplicate titles. |
| `stats` | Posts per year, provenance, authors, lengths, tags, images. `--tags` lists every tag with its count. |
| `all URL` | `fetch` then `convert`. |

The site exporters also take `--site-inputs DIR` (default `site/`),
`--out DIR` (default `site-<generator>/`), `--image-cache DIR`
(default `.image-cache/`) and `--clean`.

## Workflow

```sh
pixi run medium-archive all https://blog.example.com/ --limit 5   # smoke test
pixi run medium-archive fetch https://blog.example.com/           # re-run until "0 new"
pixi run medium-archive import-export alice-export.zip            # once per author (optional)
pixi run medium-archive compare
pixi run medium-archive import-ghost https://blog.example.com/    # if the blog was on Ghost (optional)
pixi run medium-archive compare --ghost
pixi run medium-archive convert
pixi run medium-archive lint
pixi run medium-archive stats
pixi run build-pelican                                            # or build-hugo, build-myst
```

- **Discovery** merges the sitemap, the RSS feed (about the ten most
  recent posts) and the Wayback Machine index, since Medium's sitemap
  lists only recent years. `--no-wayback` skips the last. `--urls FILE`
  fetches the listed URLs, Medium ids or post directory names instead of
  running discovery (e.g. to backfill one post's embeds). `--start`/`--end`
  are checked against each page's real publish date.
- **Missing posts.** Posts discovered but no longer served by Medium
  (including its HTTP-200 not-found page) are listed in
  `raw/missing.json` with a `wayback_url` for manual recovery. A re-run
  re-checks them.
- **Rate limits and bot walls.** A 429 is reported and skipped; raise
  `--delay` and re-run. A 403 falls back to the post's RSS body when
  there is one and marks the post `page_blocked`, so a later run asks
  for the page again. Three walled posts in a row with no fallback stop
  the run. `--cookies FILE` with a matching `--user-agent` can pass a
  light wall; `--solve-walls` opens a visible browser for a human to
  clear an interactive challenge.
- **Account exports** are the most faithful body source and carry the
  exact publish time. The fetched page still supplies tags, the updated
  date, the canonical URL and images.
- **Ghost import** keeps pages whose HTML declares a Ghost generator.
  A post also on Medium (matched by slug or title) gets the capture
  attached as `ghost.html`; `convert --prefer-ghost [--only URL]` uses
  it. Others become posts of their own.
- **Back up `raw/`**: it is the only part that cannot be regenerated.

## Conversion

Body source preference: account export, then the page's embedded editor
state (`window.__APOLLO_STATE__`), then the RSS body, then the rendered
page. `--prefer-page` forces the rendered page. The RSS body lacks
inline code and section dividers, demotes headings, and is truncated
for member-only posts, so it is used only when the page has no usable
state.

- Medium chrome (footer, tracking pixels, clap/share UI) is removed.
- The title is dropped from the body. The subtitle goes to front matter
  `subtitle` as inline Markdown. `description` is plain text, with the
  repeated title removed and a truncated summary completed from the
  subtitle. A title Medium truncated from the opening heading is
  completed from it.
- Code fences carry Medium's recorded language. Emphasis that wraps only
  punctuation is unwrapped; emphasis CommonMark will not parse is
  written as `<em>`/`<strong>`.
- Embeds:
  - gist: files inlined (code as a fence, Markdown verbatim);
  - tweet: a blockquote of the archived text, photos and date; a deleted
    tweet becomes a link;
  - Carbon: the archived code as a fence;
  - Giphy: the downloaded gif, or the mp4 as a looping muted `<video>`;
  - YouTube, Vimeo, CodePen, Spotify, SoundCloud: an `<iframe>` player
    (`PROVIDER_EMBEDS` in `convert.py`);
  - art19: a plain link;
  - anything else: an `[embed: url]` link, reported by `lint --embeds`.

  Embed content not yet fetched shows as a link or a
  `[missing embed: name]` placeholder until a `fetch` re-run backfills
  it.

### Hand-written corrections

- **`archive/fixups/`**: `*.sub` files (a `file:` line, then
  `old:`/`new:` pairs; optional `count:`, `old-regex:`, `#` comments)
  and `*.patch` unified diffs (targets `<medium_id>/<file>`), applied in
  memory by `convert` and `compare`. `raw/` is never modified.
- **`archive/tags.json`**, applied by `convert` to front matter:
  `drop` (remove everywhere), `rename` (map variants to one tag),
  `imply` (a tag entails others), `add`/`remove` (per post slug), and
  `display` (the name sites show a tag under; unset, hyphens become
  spaces).

A fixup or tags entry that no longer changes anything aborts the run.

## Generated sites

All three give posts the same URLs, rewrite links between posts to the
new pages, read `site/site.toml`, and write `redirects.csv`. Each site
directory contains its own `README.md` (what to edit, how to build, how
to write a post) and `.gitignore`.

| | Hugo | Pelican | MyST |
|---|---|---|---|
| export and build | `pixi run build-hugo` | `pixi run build-pelican` | `pixi run build-myst` |
| output | `site-hugo/public/` | `site-pelican/output/` | `site-myst/_build/html/` |
| serve (in the site directory) | `pixi run hugo server` | `pixi run pelican -l` | `pixi run myst start` |

`pixi run` finds `pixi.toml` from a subdirectory, so the serve commands
run inside `site-hugo/` etc. use the same environment. The generated
README in each site directory gives install instructions for building
it outside this repository.

### Hugo and Pelican

Both use the same card-grid theme (`src/medium_archive/templates/`) and
read posts as CommonMark (Goldmark; a markdown-it-py reader in the
generated `pelicanconf.py`) with tables, strikethrough, footnotes,
definition lists and typographer. Features:

- Paginated home of cover cards; tag and author listings with sortable
  chip indexes and per-term feeds (RSS on Hugo, Atom on Pelican); an
  archives page; a Pagefind `/search/` page.
- Posts at `/posts/<year>/<slug>/` (slug at most 55 characters), with a
  listing at `/posts/<year>/`. Tags and authors at `/tags/<slug>/` and
  `/authors/<slug>/`.
- Light/dark/system theme picker. Font and link-colour pickers for
  comparing typography candidates.
- Copy buttons on code blocks, heading anchor links, click-to-zoom
  images, syntax highlighting in both palettes.
- Share links (LinkedIn, Facebook, Bluesky, Mastodon, email) and a
  "More posts" block (by shared tags, then author, then date).
- Open Graph tags, per-post meta description and canonical URL,
  schema.org JSON-LD graph, `sitemap.xml`, `robots.txt`. A post that
  declared a canonical on another host keeps it.
- Optional logo, favicon, announcement banner, HubSpot newsletter band,
  Plausible analytics, from `site.toml`.

Site data is kept separate from generated machinery, so a built site
can be edited and rebuilt without the exporter: Hugo's
`config/_default/params.toml` and `hugo.toml`, Pelican's `site.toml`
(read by `pelicanconf.py`), and `data/tags.yaml` / `data/authors.yaml`
(display names and author profile URLs) in both.

### MyST

One page per post, a cover-image gallery landing page (myst-listing
plugin, downloaded by mystmd at build time), a chronological `archive`
page and a year-grouped table of contents. The exporter reproduces
mystmd's 50-character slug rules for `redirects.csv` and escapes
`@handle` and `$` pairs that MyST would parse as citations and math.

### Images

`raw/` and `posts/` keep originals. Sites get display copies, built
once into `--image-cache` and hard-linked into each site (copied across
filesystems):

- Card covers: 640×360 via Pillow; near-16:9 sources are cropped,
  others letterboxed.
- Photographs: capped at 1600 px, with 480/736/1104 px webp `srcset`
  variants. The first body image loads eagerly, the rest lazily.
- Line art (most PNGs): lossless webp at full resolution.
- Animated gifs: h264 mp4 at full resolution with a poster, rendered
  as `<video controls>`; they autoplay only on screen and when the
  reader has not requested reduced motion. Frames of bursts faster
  than ~30 fps are dropped, and every kept frame keeps the gif's
  timing. A clip is placed even where it is larger than the gif, for
  the pause control. An animated gif that cannot become a clip (ffmpeg,
  its libwebp or Pillow missing, real transparency, an unreadable gif,
  ffmpeg failing) stops the build with an error listing every such gif,
  unless `site.toml` asks for gifs (`animated_format = "gif"`). The
  measurements behind these choices are in `docs/gif-intermediates.md`.
- The Pelican site stores one master of each animation, frame-rate
  capped and at full size: the smaller of two lossless copies (the gif
  re-optimized by gifsicle `-O3`, or animated lossless WebP), or an
  AV1 4:4:4 CRF 28 master where that is at most 75% of the lossless
  copy (`master_max_share`). Its build makes the h264 it serves from
  the master, with the settings above, cached under `$CLIP_CACHE`
  (`.image-cache/clips/` in the pixi task). A site kept as its own
  repository then holds one small copy of each animation that any
  later format can be made from. `[images] clip_master = "none"`
  stores the h264 clip instead.

Configure with `site.toml`'s `[images]` table: `still_max_edge`,
`animated_max_edge` (0, the default for animations, disables the cap), `animated_format` (`"mp4"` or
`"gif"`), `video_crf` (default 24), `video_preset` (default `"slower"`).

### Redirects and feeds

The Hugo and Pelican sites redirect old inbound paths (Medium slug+id,
`/p/<id>`, Ghost-era) according to `site.toml`'s `redirects`:

| value | output | use for |
|---|---|---|
| `"stubs"` | meta-refresh page at each old path | GitHub Pages; any static host |
| `"file"` | `_redirects` file with HTTP 301 rules | Netlify, Cloudflare Pages |
| `"both"` (default) | both | host not yet chosen |
| `"none"` | neither | redirects configured elsewhere |

On Netlify, `"both"` disables the 301s because static files shadow
unforced rules. Changing the setting does not remove stubs left in a
previous build's `public/` or `output/`; delete that directory before
rebuilding.

Site, tag and author feeds carry the 20 most recent posts in full, with
absolute URLs.

### Building into a separate repository

```sh
git init ../blog-pelican
pixi run medium-archive pelican --out ../blog-pelican
```

`--out` is written in place: generated files are overwritten and other
files (`.git/`, `CNAME`, workflows) are left alone. Pages whose post has
left the archive are reported; `--clean` removes them by emptying
`--out` first, keeping `.git/` and git-ignored files (or, outside a
git tree, the generator's build directories). Output is byte-identical
across runs given the same archive and the same Pillow, ffmpeg and
gifsicle versions. Install ffmpeg before the first commit if the
archive has animated gifs.

## `site.toml`

`site/site.toml` holds what the sites say about the publication. Every
key is optional; image paths are relative to `site/`. The file itself
documents each key in comments, as do the copies the exporters write
(`site-pelican/site.toml`, `site-hugo/config/_default/params.toml`).

| key | purpose |
|---|---|
| `title`, `description` | site name and tagline, also used by feeds |
| `base_url` | domain the site is served from; all absolute URLs (feeds, stubs, Open Graph, share links) use it. Exporters warn when unset. |
| `locale` | page language (default `"en"`) |
| `intro` | landing-page blurb (Markdown) |
| `footer` | line under every page (Markdown); `{year}` is the build year |
| `avatar`, `favicon` | header mark and browser-tab icon |
| `logo`, `logo_dark`, `logo_link` | wordmark replacing the avatar and title, its dark-palette variant, and where it links |
| `announcement` | banner above the header: an http(s) URL fetched client-side, or literal HTML |
| `newsletter` | table: `heading`, `hubspot_portal`, `hubspot_form` (required), `hubspot_region` (default `"na1"`) |
| `redirects` | see [Redirects and feeds](#redirects-and-feeds) |
| `noindex` | `true` blocks search engines (for previews) |
| `plausible` | Plausible script URL (Hugo and Pelican only); the preview workflow removes it |
| `twitter` | `@handle` for `twitter:site` and structured data |
| `profiles` | publication URLs elsewhere, for structured data `sameAs` |
| `share_image` | `og:image` for pages without a cover |
| `images` | see [Images](#images) |
| `hugo` | Hugo-only overrides of `locale`, `avatar`, `logo`, `logo_dark`, `favicon`, and a `[hugo.params]` table merged into `params.toml` |
